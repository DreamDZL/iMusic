# 汽水搜索与播放链路验证

## 范围与接入门槛

用户要求先验证搜索与播放，再将 iOS 来源调整为聚合、酷我、酷狗、QQ 音乐、网易云、汽水。不再要求保留历史咪咕数据兼容；不得因此删除其他平台数据。

本轮只做只读联网验证，未修改来源列表、持久化、播放器或 LX 桥接逻辑，未构建新 IPA。现有应用仍使用本地下载和启用的 LX 音源播放，不应把外部验证通过写成 iOS 集成已完成。

## 公开接口实测（2026-11-14）

参考 MIT 开源项目 [GSQZ/qishui-music-api](https://github.com/GSQZ/qishui-music-api)，固定源码提交 `924add376cadf8a2268f11999051eb976e3b8e0d`，审阅后在临时目录调用其公开目录及未加密播放解析模块。未安装依赖、未登录账号、未提取其他应用凭据，也未解密受保护音频。

请求链路：

- `open.qishui.com/api/luna/v1/platform/client/token/get/`：HTTP 200，业务码 0。临时客户端令牌仅在验证进程内使用。
- `open.douyin.com/api/luna/v1/platform/search/`：HTTP 200，业务码 0，返回字符串歌曲 ID、标题、歌手、时长和目录元数据。
- `open.douyin.com/api/luna/v1/platform/media/mget/`：HTTP 200，业务码 0。
- 返回的受信任播放信息地址：HTTP 200；媒体地址的字节范围请求：HTTP 206，`audio/mp4`。

每首仅读取最多 262,144 字节到内存，并交给本机 FFmpeg 从标准输入解码 3 秒到空输出。三个样本解码退出码均为 0，输出时间均为 3 秒。没有下载完整歌曲；服务器的 full/preview 标记不等于已验证完整歌曲的每个字节或播放时长。

样本：

- 关键词「晴天」：首项 `7676337516358617115`，标题「晴天」，歌手「晚风纯音」，目录时长 237,336 ms。返回 `preview=false`、`standard`，前 3 秒解码成功。**不是周杰伦原唱样本。**
- 关键词「海阔天空」：首项 `7645708847394900008`，标题「海阔天空（Cover beyond）」，歌手「后知后觉」，目录时长 314,808 ms。返回 `preview=false`、`standard`，前 3 秒解码成功。**是翻唱样本。**
- 关键词「陈奕迅 孤勇者」：首项 `7036414012917024769`，标题「孤勇者」，歌手「陈奕迅」，目录时长 256,000 ms。返回 `preview=true`、`high`，前 3 秒解码成功。**仅验证试听，不能声称完整播放通过。**请求参数使用 standard，但解析器可能选择服务器实际提供的其他档位；不得仅凭请求值显示实际音质。

三个关键词均取前 3 项和 offset=3 的下一页，各返回 3 项，本次样本两页无重复 ID。汽水 ID 超过 JavaScript 安全整数范围，必须按字符串保留，不能转成 JS Number 后再发送给 LX。

一个随机无意义关键词也返回 3 项及 `hasMore=true`。因此公开接口可能返回模糊匹配或推荐，不能把「非空」等同于「找到精确目标」，也不能据此宣称无结果状态已验证。接入时需要检查相关性、分页和空结果语义。

## 用户 LX 音源链路：后端样本验证

此前读取过的第二份脚本声明 `qs` 的 `musicUrl` 动作，并兼容将传入的 `sd` 转为 `qs`；没有搜索或歌词动作。声明不能替代真实歌曲解析、媒体下载及解码验证。

本轮通过私密卡片收到的地址主机是 `lx.xiagua.top`，与此前第二个地址不同。使用系统 HTTP 客户端和 Node.js HTTPS 请求时连接被重置；公开根地址访问亦失败。未禁用 TLS 校验、未用第三方代理转发密钥、未取得或执行该脚本。不能将网络失败写成「不支持汽水」或认定服务永久不可用。

随后用户重新提供了此前第二个音源的地址；脚本成功下载。静态审阅确认其将 `sd` 转成 `qs`，并将歌曲字符串 ID、请求音质及密钥发送给对应服务端。**没有执行该第三方脚本**：验证程序仅复现其 `qs` 的 `musicUrl` HTTP 请求，限制到脚本指定的 HTTPS 服务，并且不在输出、报告或仓库中记录密钥及签名媒体 URL。

三个上述搜索结果均在 `128k` 请求下返回 HTTP 200、业务码 200 和播放地址。媒体请求最多读取 262,144 字节，通过 FFmpeg 解码 3 秒；媒体仅允许公网 HTTPS，不跟随重定向：

- 样本 `7676337516358617115`：HTTP 206、`audio/mp4`，前 3 秒解码成功；容器声明 237.336 秒，与目录时长一致。
- 样本 `7645708847394900008`：一次 HTTP 206、前 3 秒解码成功；另一次返回 HTTP 302，按安全策略未跟随，未验证跳转链。
- 样本 `7036414012917024769`：HTTP 206、`audio/mp4`，前 3 秒解码成功；容器声明 256 秒，与目录时长一致。该结果来自用户 LX 服务，不是前述公开接口的试听结果；容器时长相符仍不足以证明整首音频或歌曲身份完全正确。

这是按脚本构造的**后端 HTTP 样本验证**，不是脚本在 JavaScriptCore 中的运行结果，也不是 iOS AVPlayer 或完整歌曲播放验证。服务可变、签名链接会过期，不能保证所有歌曲可用；对 302 的合法跳转需要在实际客户端安全处理。用户新提供的另一个脚本地址连接失败，无法判定其能力。

私密下载地址、密钥、临时客户端令牌及签名媒体 URL 均不写入仓库。

用户随后提供了本机 StellarWave v3.2.0 JSON 音源。静态检查其 `script`：注册平台仅为 `tx`、`wy`、`kw`、`kg`、`mg`，仅注册 `musicUrl`，并无 `sd`、`qs`、`soda` 或 `qishui` 的平台处理；后端分派也只覆盖这五种平台。因此不能用它验证汽水 ID 的原平台 LX 解析。该文件与此前声明 `qs` 的第二个音源不是同一脚本；本次未执行此不受信任脚本，也未验证其他平台的后端可用性。

## 当前结论

公开目录及部分未加密媒体可用，是候选接入依据；存在翻唱、试听及搜索相关性限制。用户音源后端可解析上述样本，但 iOS 内的 LX 脚本及 AVPlayer 链路尚未端到端验证；不应直接反转 `.sd` 的过滤条件，或把咪咕改名为汽水来宣称完成。

下一步实现并测试目录适配、`qs`/`sd` 映射与歌曲 ID 原样传递，并对用户可见来源和聚合逻辑按能力分别配置。Windows 上的网络与 FFmpeg 实测不代替 iOS AVPlayer、Swift 编译及真机播放验证。
